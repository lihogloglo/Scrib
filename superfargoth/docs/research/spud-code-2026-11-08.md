## Verdict

Their published numbers (`docs/PERF_CHANGES.md`): a 12-section tour of the real game averages **~375 fps, GPU mean
~1.75 ms**, frame ≈ GPU time + a 0.76 ms present. Hardware and resolution are not stated. It is Skyrim's 2011
forward lighting with 4x MSAA: no ray tracing, no upscaler, no volumetric clouds. So the GPU numbers do not compare
with ours (bevyrrowind `docs/perf.md` "Frame budget": 11 ms at 1440p + DLSS Q on the 4060 Laptop). The **CPU side
does compare**: SPUD's main thread has nothing left to cut, ours is render-thread bound (hard problem H1).

The one idea that matters most: **static world geometry never becomes per-view, per-entity work.** It is a flat
array per loaded cell, culled in a tight loop and drawn as one multi-draw-indirect per pipeline state. There is **no
GPU culling** (no culling compute shader in `shaders/`): data layout and instancing per (submesh, LOD) are enough.
That is the CPU twin of the Clockwork design H1 already cites, and it is shipped and measured.

## Ranked items

### 1. The static draw path (H1, ROADMAP 1.2 / 1.9)

How it works (`src/engine/space.cpp` `Space::finalize_ref` and the draw loop around line 1000;
`src/render/renderer.cpp` `build_mesh_draws`, `record_runs`):

- **Per loaded cell, a plain array of references.** Each holds a world bounding sphere, `lod_error[3]` (metres, times
  the reference's scale), an instance slot, flags. The cell keeps its AABB.
- **Instance data is written once** into a persistent host-visible GPU table (`InstanceTable`) when the reference
  becomes drawable; freed slots go back through a deferred free. Nothing about statics is rewritten per frame.
- **Per view:** cells sorted by distance → cell AABB vs frustum → terrain horizon test (item 3) → per reference:
  sphere vs frustum only if the cell intersects, sub-pixel cull by pixel radius, room cull, occluder planes, LOD pick
  (item 2) → `DrawItem{mesh, instance, distance², variant, lod}` (a POD, ~40 bytes).
- **Draw building: a three-pass counting sort** into a per-frame host-visible arena. Pass 1 counts instances per
  (draw group, LOD) and buckets groups by a dense pipeline-state slot. Pass 2 writes one
  `VkDrawIndexedIndirectCommand` per (group, LOD) with `instanceCount` = visible copies, in state order, turning
  the counts into write cursors. Pass 3 writes instance indices. Recording is one `vkCmdDrawIndexedIndirect` per
  state run, a pipeline bind only when it changes, cull/depth/bias as dynamic state.
- **One vertex arena and one index arena** for every mesh (VMA virtual blocks, `GpuArena`), materials in a GPU table
  read by buffer device address, bindless textures. Draw calls ≈ distinct pipeline states, not meshes.
- **Sun cascades use the same path** (`renderer_shadows.cpp`): per-cascade sphere test, bucketed by caster bits.
- Blended draws are the exception: sorted back to front, one command each.

Why it is relevant here: H1 found that halving mesh entities (precombine) did not move the frame, and the best
hypothesis is Bevy's per-view prepare/queue/batching × ~6-8 views. SPUD's answer is not merging; statics simply never
enter that machinery. In Bevy the equivalent would be:

- one render-world item per streamed cell (or per worldspace), owning a POD reference table baked per cell;
- our own per-view cull + LOD pick (CPU first, as SPUD shows it is enough) writing indirect args into Bevy's mesh
  allocator slabs, with bindless materials;
- shadow views (sun cascades, lamp cubes) fed from the same table, which also closes the perf.md "Lead (not yet
  tested)" about `NoIndirectDrawing` sun views culling nothing.

**This conflicts with the hard-problems brief "never render-world injection": owner call.** A narrower first test that
stays inside the rule: count per-view work items on `balmora_walk` (the H1 first step), then estimate what one
item per cell would remove.

### 2. One pixel-error rule for LOD, no draw distance (`docs/ARCHITECTURE.md` "LOD")

- Each simplified level stores its geometric error in metres (meshoptimizer, 3 levels over the same vertices, vertex
  colour weighted in because it is the art's baked shading: `src/importer/convert/mesh_import.cpp`).
- Selection: the coarsest level with `e² · (pixels_per_radian / lod_pixels)² ≤ d²`. Presets change only the
  threshold: Ultra 0.5, High 1, Medium 2, Low 4 px. Far terrain (CDLOD-style nodes) uses the same threshold.
- Sub-pixel references are culled by pixel radius. Streaming radius decides residency at full detail, never what is
  drawn. Swaps happen below a pixel, so no fades.

`sf_lod` already stores geometric error (`levels.rs`, `cluster.rs`), but our presets are a view-distance bias + a
size cutoff in reference px + rings (perf.md "Render options"). One px threshold would make quality follow
resolution and FOV (under DLSS: the internal resolution's pixels per radian) and remove the ring tuning.

### 3. Cheap CPU occlusion

- **Terrain horizon** (`Space::land_hides`, ~30 lines): per cell the land's *minimum* height (conservative). For a
  cell more than 4 cells away, step from the eye to 9 points on its AABB top (+3 m margin) through the cell grid; if
  the land floor blocks all 9, the cell is culled. The H1 Greatness7 lead (horizon culling from a max-height grid,
  ~41 % fps in dense areas) is the same idea; SPUD shows it is small.
- **Rooms and portals** inside interiors, from Skyrim's room markers; occlusion planes for exteriors (with a 30 m
  near limit for "far-only" occludable refs). Morrowind has no room markers: the bake could generate them per
  interior.

### 4. Stutter discipline (ROADMAP 1.1, J7 pipeline warm-up, ROADMAP 1.x precompilation item)

- Hard rule (SPUD `CLAUDE.md`): **no IO, parsing or pipeline creation on the render thread**; `PERF_CHANGES.md` moves
  every main-thread file read it finds to a worker, even single `stat` calls.
- **Their stutters only showed with a cold file cache** (first-use decodes on the main thread: 23 ms to open one cold
  UI file, 19-25 ms for a navmesh decode, 24-35 ms grounding arriving actors). Method: evict the file cache, run the
  tour, and name every frame over 8 ms by trace zone (`SPUD_TRACE_SLOW=8`). Our hitch table is mostly from warm runs.
- **Every pipeline is built up front**, in parallel, through a persistent `VkPipelineCache` saved to disk
  (`src/render/pipelines.cpp`). The variant space is kept small on purpose: cull mode, front face, depth test/write
  and depth bias are dynamic state; only blend factors are baked; a few specialization constants. Supports the
  ROADMAP "Shader/pipeline precompilation" candidate: shrink the key space first, then warm it at a loading screen.

### 5. Tooling

- **Image-history audit** (`tools/audit/history_audit.py`): each pose is rendered after flying there from elsewhere
  and again from a fresh process; ≤ 1 % of pixels may differ, and the first must match itself 30 frames later. A
  static half greps the renderer and shaders for whole-image temporal techniques. **Not for us as is:** it is a
  pixel diff, and the owner rule (`CONTRIBUTING.md` "Tests and visual checks", 2026-11-01) bans agents judging
  rendering from image comparisons; it would also need DLSS off. The part that transfers is picture-free: compare
  what is *drawn* (per-view draw lists, LOD picks, resident cells as counts or hashes) after flying to a pose versus
  starting there, which catches route-dependent streaming without an image.
- **Every cross-frame GPU resource declares a lifetime** (`Lifetime::simulation` / `cache`) and must be on an
  allowlist in `src/render/device.cpp`, or startup throws; the list is documented in `docs/RENDERING.md`.
- **Machine gate** (`tools/gate/gate.py`): a broker hands out shared passes (builds, headless checks; one build at a
  time) and exclusive passes (perf). Before and during an exclusive run it watches for heavy work that bypassed the
  gate; a contaminated run is flagged and re-queued (exit 75 if never clean). Stronger than our `.sessions` +
  `cargo_turn.sh` + per-run quiet-machine wait.
- **Calibration bench** (`tools/perf/scenarios/calibration.bench`, a bare present) run before perf work. It caught a
  machine-level slowdown (bare present 0.17 → 0.76 ms with no code change) that would otherwise read as a regression.
- **One command language** (`.osc`) for benchmarks, tests and live control; `state <file.json>` dumps pose, streaming
  counts and per-pass GPU medians over the last 64 frames. Compare with our `perf suite` + BRP.

### 6. Compiled runtime formats

Only the importer reads Skyrim formats; the engine reads chunked FourCC containers (`docs/formats/container.md`),
each with a spec page and a version bumped with any change. One `.osw` per worldspace holds the cell grid, terrain,
placed references (with bounds and flags item 1 needs), mesh/texture tables, doors and rooms. Imports are keyed by
content hashes and deterministic. We already bake (`sf_bake`, cooked models); the takeaway is to bake the
draw-relevant reference table per cell in the shape item 1 consumes, so streaming in a cell is a read, not record
lookups.

## Not taken

- **No-TAA rule** (`docs/RENDERING.md`): we chose DLSS (owner decision). Their warning still applies: many techniques
  quietly rely on TAA to hide noise (few-sample AO, dithered fades, stochastic transparency).
- **Visibility buffer:** measured in forest, best case ~0.4 ms, expected 0-0.2 ms after losing hardware interpolation
  and specialised shaders; not built. Useful data point if we consider one.
- **Present from its own thread / wait on the frame fence before presenting** (their largest fps gain, 266 → 373):
  inside wgpu for us; our `render/present` and `render/acquire` counters already watch it.

## Pitfalls they hit (worth a test here)

From `docs/PERF_CHANGES.md`, all with fix-in / fix-out evidence:

- actors in a space behind a door stepped every frame and were skinned twice with a door in view, overwriting bone
  rows the GPU was reading (device loss);
- a device wait raced the upload thread's submit (device loss on big loads such as a resolution change);
- a new world was spotted by address alone and could land at the old one's (crash on travel);
- loading screens waited on an effect system that does not run behind a loading screen (30 s hangs).
