# Automatic grading of generated clips (AG0, 2026-11-12)

Research + measurement, no repo code. Question (owner): rating 228 Kimodo takes by hand "felt like forever"; can a grader
reject the obvious failures and rank the rest? Tags: [K] from memory (not re-read today), [V] measured here.
Scripts (scratchpad, not in the repo): `ag_feat.py` (features), `ag_an.py` / `ag_thr.py` / `ag_gate.py` / `ag_lr.py`
(analysis). Labels: `verdicts.toml` snapshot of 2026-11-12, **175 rated**: 106 reject, 49 maybe, 20 keep (cycles 67,
starts 42, stops 18, pivots 24, turns 24; walk starts and stops are mostly unrated).

## 1. Research: how others grade motion

| Method | Needs a model? | What it catches | Fit for us |
|---|---|---|---|
| Foot skating (ratio of contact frames whose foot speed > threshold, or cm slid per contact) [K: Kovar 2002 cleanup; used in MDM/PhysDiff tables] | numpy | sliding feet | Have it (`clipstats`). Strong signal at forced speed. |
| Foot penetration / floating (min foot height, time with no contact) [K: PhysDiff, ICCV 2023] | numpy | sinking, flying | Have flight time. Floor is flat here. |
| Jerk / smoothness (max, p99, LDLJ) [K: Flash and Hogan; Balasubramanian 2015] | numpy | pops, pivot snaps | Have it. |
| Physical plausibility: CoM over support polygon, ZMP, contact forces [K: PhysDiff projects every denoise step through a physics sim] | physics sim | falling-over poses | Too heavy for a screen; a CoM-vs-feet check is ~20 lines but unproven for gait. |
| Self-penetration (limb capsules vs torso capsule) [K: standard in IK/retarget QA] | numpy, rig-dependent | arm through torso | Needs the TARGET body (our mesh is thicker than SOMA). Source-space version found nothing (see 2). |
| Joint limits (knee hyperextension, elbow, spine bend) [K] | numpy + limit table | impossible poses | Cheap; knee/spine curvature measured below. |
| Cycle periodicity / loop seam error (pose + velocity distance between best matching frames) [K: motion-matching DB prep, Clavet GDC 2016] | numpy | clips that cannot loop | Measured: `seam_err` is tiny for all (0.01-0.05); not discriminating. |
| Prompt accuracy: speed, heading, path error vs the constraint [K: Kimodo/MDM "constraint error" metrics] | numpy + `.prov.json` | wrong speed/turn | Have the constraint error in prov; added turn-angle and speed ratio. |
| FID, R-precision, diversity, MM-Dist over a motion-text embedding [K: Guo 2022 T2M; TMR, Petrovich 2023] | learned encoder | set-level realism / text match | Dataset metrics, not per clip; poor ranking of single takes. |
| Perceptual critic: MotionCritic (Wang et al., "Aligning Human Motion Generation with Human Perceptions", ICLR 2025) [K] | learned (trained on human ratings) | "looks wrong" | Closest to the owner's need; trained on a different skeleton/style, needs a port to SOMA and a GPU env. Park until our own labels exist to test it. |
| Game QA: UE Animation Insights / `ShowDebug Animation` (visual only) [K]; Ubisoft motion-matching DB tags and automated contact/foot-lock curve validation [K, GDC talks]; mocap vendors' automated "solve error" and gap reports [K] | numpy | structural data faults | Studios gate on structural checks (contacts, loops, bone limits) and leave taste to a human pass. Same split as here. |

Takeaway [K]: the field grades *physical* faults automatically and *taste* with people or learned critics fitted to
people. We have the people's labels, which is the scarce part.

## 2. Calibration (source space, SOMA-77, 30 fps)

Features per clip (all on the source BVH): foot skate (cm/s per contact), flight, jerk max/p99, elbow/wrist distance to the
spine axis in shoulder widths, upper-arm abduction, elbow flexion, clavicle drop, trunk lean and curvature, head offset,
arm swing amplitude, pelvis bob/sway, shoulder-vs-pelvis twist, cadence/contact alternation, loop-seam error, path error,
speed ratio vs the gait target, turn error and direction. AUC = P(reject scores above keep+maybe); "n" = rejects / ok.

**The label is mostly a property of the prompt group, not the take.** Reject rate by group [V]:

| Group | reject / n | Group | reject / n |
|---|---|---|---|
| sprint cycle (path-forced) | 16 / 18 | walk pivot l180 | 9 / 12 |
| walk cycle (path-forced) | 16 / 18 | run pivot l180 | 10 / 12 |
| run cycle (path-forced) | 13 / 18 | run start f / b180 / l90 | 6 / 5 / 2 of 12 |
| walk cycle `.free` | 1 / 6 (4 keeps) | run stop | 7 / 18 |
| run cycle `.free` | 3 / 6 | turn l180 / l90 | 7 / 5 of 12 |

70 of the 106 rejects sit in six groups with >= 70 % reject rate. A leave-one-prompt-group-out logistic model on 16 metrics
has **AUC 0.54** (chance): the metrics do not yet transfer across prompts, so a learned per-take ranking is not
supportable at n = 175. Within-type, single-metric results (rejects vs keep+maybe):

| Type (n rej / ok) | Best metrics [V] | AUC |
|---|---|---|
| cycles (50 / 17) | skate 60 vs 25 cm/s; lean 6.2 vs 3.6 deg; curvature mean 19.0 vs 17.3 deg; jerk p99 2675 vs 1096; upper-arm flare 30 vs 25 deg | 0.65-0.68 |
| walk cycles (17 / 7) | flight, skate 27 vs 12, pelvis bob 0.07 vs 0.04-0.05 m (forced path walks bounce); alt_frac; seam (ties) | 0.8-0.89 (confounded with path-forced vs free) |
| starts (18 / 24) | **low arm swing** 1.25 vs 1.81 shoulder widths; shoulder-pelvis twist 37 vs 46 deg; pelvis bob; wrist-to-trunk | 0.74-0.83 |
| turns (12 / 12) | turn-angle error 9.8 vs 3.5 deg; lean; zero foot steps | 0.78-0.80 |
| pivots (19 / 5) | jerk p99 (run pivots 3k-65k), skate 24-175, flight | 0.65-0.74; **n = 5 ok, no weight** |
| stops (7 / 11) | seam, skate, elbow flexion | 0.71-0.75, n too small |

Findings that contradict the brief:
- **Arm-to-chest does not show in source space.** Elbow and wrist distance to the spine axis is 0.65-1.0 shoulder widths on
  every group; "inside torso" never fires (0 of 228 under 0.45 sw). Arm tuck on screen comes from the retarget onto our
  thicker body (diagnosed separately), so this metric must run on the retargeted clip. The nearest source proxy is low
  arm swing in starts.
- **Wrong direction is not a reliable reject.** Right-turning pivots were *kept or maybe* (5 of 17), the 7 left-turning pivots
  were all rejected. Only turn-in-place direction matched (4 of 5 wrong-way rejected). Mirroring makes direction a
  relabel, not a fault; magnitude and "no turn at all" (two `turn.l180.2` takes turn 1 deg) are the faults.
- Loop-seam error and contact alternation do not separate anything at this resolution (my contact detector counts double
  steps on slow free walks; needs the cook's contact curves instead).

## 3. Grader design

**Principle (owner: "easier to say it doesn't work than that it is okay"):** automate rejection only; ranking within
the survivors stays a mild, explainable score; the owner's keep/maybe stays the truth.

**Hard gates (auto-reject, printed with the failing gate name).** First four are physical and not fitted to labels:

| Gate | Rule | Rejects caught / keep+maybe flagged |
|---|---|---|
| `skate` | skate >= 60 cm/s per contact (cycle, start, stop, pivot) | 26 / 6 (1 keep) |
| `jerk` | p99 body-joint jerk >= 5000 m/s^3 | 18 / 4 (0 keep) |
| `turn_mag` | in-place or pivot: turn angle off the prompt by > 9 deg | 7 / 1 |
| `no_step` | turn-in-place with zero foot contacts | 6 / 1 |
| `turn_dir` | turn-in-place turning the wrong way (flag, mirror candidate) | 4 / 1 |
| `arms_flared`, `hunch`, `stiff_arms`, `walk_bob` | fitted thresholds (see section 2): upper arm >= 36 deg from vertical, trunk curvature >= 22.4 deg, start arm swing <= 1.44 sw, walk pelvis bob >= 6.5 cm | 13/1, 14/1, 12/2, 8/2 |

**In-sample result on the 175 rated (thresholds partly fitted on them, so optimistic): union of all gates catches 61 of 106
rejects (58 %) and wrongly rejects 12 of 49 maybe and 2 of 20 keep (20 % of keep+maybe).** Physical gates alone: 41 / 106
(39 %), flagging 9 maybe + 1 keep (14 %). Expected out-of-sample: lower recall for the four fitted gates. Gates that are
group-level in disguise (all path-forced sprint clips fail skate) are correct: that is the signal to regenerate the prompt.
Do not auto-delete: gated clips stay in the browser behind a filter.

**Score for ranking (keep+maybe only, 0-100, display only).** Weighted distance of each metric from the median of the
owner's *kept* clips of the same type (robust z): skate, jerk p99, arm swing, twist, trunk curvature, pelvis bob, turn
error, flight. Weights start equal; refit as keeps accumulate (20 now: too few to fit, enough to take medians per type).
No claim beyond "clips closer to what the owner kept sort first".

**Group-level triage (the biggest saver).** When >= 4 of 6 takes of a prompt hit a gate, mark the *prompt* failing and
skip showing it; suggests a recipe change (path speed nearer the model's natural ~3 m/s then retime, per gait card 3.3).

**Where it lives.**
- Python `motiongen grade <dir>` on the source BVH, next to `clipstats` (numpy, fast: 228 clips in 6 s here). Owns skate,
  jerk, turn, step count, bob/swing/twist, group triage. Writes `grades.json` beside `verdicts.toml` (clip -> score,
  gates). Runs inside the generation loop right after export.
- Rust, on the retargeted clip in `clip-preview` (target body): arm-to-chest / elbow-in-torso capsule check, retarget-added
  tuck, hand-vs-torso penetration. Needs the target skeleton; cannot be done in Python without duplicating the retarget.
- Both feed one `grades.json` schema (`gate` list, `score`, `source: py|rs`) read by the browser.

**Browser (`clip-preview --browse`).** Overlay line "score 73 | gate: skate 112 cm/s"; key to sort the group by score
(gated clips last); "candidates only" mode (default on) hides gated clips and shows the top 3 per group; the owner's
Y/N/M still writes `verdicts.toml`, which the grader reads back for recalibration.

**Generation loop.** generate N=6 -> `grade` -> keep the top 3 un-gated per prompt for owner review; prompts with 0 survivors
go back as "regenerate with changed constraint". Cuts the owner's pass from 228 to roughly 80-100 clips here.

## 4. Slices (one deliverable each)

1. **AG1** `motiongen grade` (Python): the physical gates + `grades.json` + printed table; test = exact assertions on
   synthetic BVH (skating foot, jerk spike, turn) and a printed calibration table over `loco1` (sanity only).
2. **AG2** browser integration (Rust): read `grades.json`, overlay, sort, candidates-only mode. Visual check registered, owner signs off.
3. **AG3** fitted gates + per-type "kept" medians score; refit script `motiongen calibrate` reading `verdicts.toml`; report
   precision/recall with leave-one-group-out, per owner batch.
4. **AG4** target-body arm/chest check in Rust on the retargeted clip (after the arm diagnosis lands).
5. **AG5** (parked) trial MotionCritic or a TMR-style embedding on our labels; only if AG3's LOGO AUC stays < 0.7.

## 5. Open questions

- Owner: is a wrong-way turn a reject or just a mirror? (data say mirror; this changes `turn_dir`).
- Owner: should the walk path-forced group (16/18 rejected, speed and skate fine) be explained? The numbers show only
  bounce/jerk differences from the `.free` walk that was kept; there may be a quality (stiff, robotic) the metrics miss.
- The six run/sprint cycle keeps and maybes have the same skate/flight as rejects; the owner may be rating on something
  else (cadence, arm pump). Ask what made the 5 kept cycles different.
- Calibrate again after the retarget and arm fixes: the labels were made on the old retarget, so arm and trunk gates may shift.
- Rated clips mostly reflect the first-loaded groups; walk starts/stops (30 clips) are unrated and untested.
