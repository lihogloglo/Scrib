# Live feature toggles and options-menu flow: industry and Bevy 0.20 (2026-11-23)

Slice R3 of session `feature-toggles`. Research only. Builds on `menus-settings-industry-2026-11-11.md` (sections 4 and Recommendations). Source for Bevy paths: `~/.cargo/registry/src/index.crates.io-*/`. Searches were quick lookups; items marked "unverified" were not confirmed on a primary page.

## 1. Live feature toggles in shipped engines

**Unreal Engine.**
- Show flags are per-view rendering bits, toggled in game with the `show` command or `ShowFlag.<Name> 0/1` (e.g. `ShowFlag.PostProcessing 0`); some are fixed in shipping builds. View modes (ShaderComplexity, QuadOverdraw) are a separate command. Sources: [UDK ShowFlags](https://docs.unrealengine.com/udk/Three/ShowFlags.html), [FEngineShowFlags](https://dev.epicgames.com/documentation/en-us/unreal-engine/API/Runtime/Engine/FEngineShowFlags), [forum thread](https://forums.unrealengine.com/t/why-is-showflag-volumes-1-seem-not-working-in-game/290324). The UDK page is UE3-era; UE5 names are unverified.
- Console variables carry a "set by" priority. `SetByScalability` is low (just above the constructor default) and `SetByConsole` is highest; a lower-priority write is ignored with a warning. Source: [Lyra scalability guide](https://dev.epicgames.com/documentation/unreal-engine/scalability-and-device-profiles-in-lyra-sample-game-for-unreal-engine), [EConsoleVariableFlags](https://dev.epicgames.com/documentation/en-us/unreal-engine/API/Runtime/Core/EConsoleVariableFlags). Do not copy the numeric values, they differ by version. This matches our layering (default < preset < user < console < command line); Epic's chain is the same idea with more rungs (project settings, device profile, game setting, scalability, console).
- Scalability groups `sg.ShadowQuality`, `sg.GlobalIlluminationQuality`, etc. map a level (0 Low to 3 Epic) to a bundle of `r.*` cvars via `BaseScalability.ini`; Lumen quality is driven by the GI and Reflections groups. Device profiles apply after groups and override them. Source: [Scalability reference](https://dev.epicgames.com/documentation/unreal-engine/scalability-reference-for-unreal-engine), [Lumen guide](https://dev.epicgames.com/documentation/unreal-engine/lumen-performance-guide-for-unreal-engine). This is the same shape as our presets-as-tunable-bundles.
- Cost readout: `stat gpu` shows per-pass GPU time, `ProfileGPU` dumps a pass/draw tree (UI or text, `r.ProfileGPU.ShowUI`), custom counters via `SCOPED_GPU_STAT`; drivers may re-optimise shaders seconds after first use, so wait before trusting a number. Source: [UE 4.27 GPU docs](https://docs.unrealengine.com/4.27/TestingAndOptimization/PerformanceAndProfiling/GPU), [stat commands](https://dev.epicgames.com/documentation/en-us/unreal-engine/stat-commands-in-unreal-engine). In UE the switch and the cost are separate tools you use side by side; there is no per-switch cost column.

**Unity HDRP.** Frame Settings are per-camera feature flags; the Rendering Debugger temporarily overrides them per camera without changing camera data (columns Sanitized / Default / Overridden). A Frame Setting cannot enable something the HDRP Asset disabled. The window needs a Development Build and "Runtime Debug Shaders", and has a runtime UI (`enableRuntimeUI`). Sources: [Frame Settings 17](https://docs.unity3d.com/Packages/com.unity.render-pipelines.high-definition@17.0/manual/Frame-Settings.html), [Rendering Debugger reference](https://docs.unity3d.com/Packages/com.unity.render-pipelines.high-definition@16.0/manual/rendering-debugger-window-reference.html). Useful idea: a toggle can only turn off what the build/quality tier compiled in, and the debug override layer is separate from authored data.

**Source engine.** Convars have flags: `FCVAR_CHEAT` (blocked unless `sv_cheats`), `FCVAR_ARCHIVE` (saved to config; the wiki advises never archiving a cheat cvar), `FCVAR_NOT_CONNECTED`, `FCVAR_SPONLY`, `FCVAR_REPLICATED`. Source: [Console command flags](https://developer.valvesoftware.com/wiki/Console_command_flags). Shows the standard answer to "who may set it": flags on the variable, not two variables.

**Frostbite.** FrameGraph makes debug visualisation a graph node; an unconnected debug pass is culled. Passes are declared units, which is what makes a per-pass switch cheap. Source: [FrameGraph slides](https://www.slideshare.net/DICEStudio/framegraph-extensible-rendering-architecture-in-frostbite). No public talk found on Decima, RAGE or REDengine debug menus (not covered).

**OpenMW.** F3 and F4 show OSG stats tables (frame, engine, resource); collection costs performance; keys are hard-coded (issue asks to expose them). Source: [HOWTO-benchmark](https://git.cijber.net/mirror/openmw/src/branch/master/scripts/HOWTO-benchmark.md), [issue 8719](https://gitlab.com/OpenMW/openmw/-/issues/8719).

**Standard shape (synthesis).** One registry entry per switch, holding: stable name, type and default, `apply` kind (live / on next load / restart), an owner layer (who last set it, with priority), an audience flag (player-visible vs dev-only vs cheat), a persistence flag (archive or not), a group, and optionally a cost source (a GPU pass or CPU system label). Engines keep dev and player options on one variable: the player UI and the console both write the same variable at different priorities (UE `SetByGameSetting` vs `SetByConsole`; Source `ARCHIVE` vs `CHEAT`). The debug panel is a second view over the same registry, not a second store. Unity's per-camera override layer shows the temporary-override pattern: debug writes never persist.

## 2. Player-facing per-feature settings

Evidence found is thin; much of the usual claims are secondhand.
- Nixxes ports (Spider-Man Remastered): presets Very Low to Very High that rewrite the individual settings below; settings apply without restart ([Laptop Mag](https://laptopmag.com/features/spider-man-remastered-this-is-how-it-runs-on-pc), [Nixxes tuning page](https://support.nixxes.com/hc/en-us/articles/48438642781459-PC-performance-tuning)). A VRAM bar was not confirmed in search; third-party guides give texture VRAM tiers ([Sportskeeda](https://sportskeeda.com/esports/marvel-s-spider-man-remastered-tech-guide-optimal-settings-best-performance)). Hardware-gated options (frame generation needs RTX 40) are shown disabled with a reason.
- Cyberpunk 2077: Graphics and Video tabs, a Quick Preset that becomes Custom when you edit a setting ([GameRevolution](https://www.gamerevolution.com/guides/669192-cyberpunk-2077-pc-best-settings-guide-nvidia-amd)). Live preview, RDR2, Alan Wake 2 and BG3 layouts were not confirmed (not covered).
- Common pattern worth adopting (consistent with the 2026-11-11 note): preset plus computed Custom, per-setting description, disabled-with-reason for unsupported hardware, apply live where possible and confirm/revert for display mode.

## 3. Menu and window flow

- UE CommonUI: `UCommonActivatableWidgetStack` shows and activates only the top widget; all others are deactivated; popping reactivates the one below. A root content widget can never be removed. Sources: [stack API](https://dev.epicgames.com/documentation/unreal-engine/API/Plugins/CommonUI/UCommonActivatableWidgetStack), [Python API](https://dev.epicgames.com/documentation/en-us/unreal-engine/python-api/class/CommonActivatableWidgetStack). Forum threads show the default also hides the previous widget, and people ask how to keep it visible ([thread](https://forums.unrealengine.com/t/commonui-how-to-push-a-widget-and-not-have-the-previous-widget-disappear/1521233/2)). So "lower page hidden" is the default and keeping it visible is an explicit opt-in. Our bug (earlier windows stay visible and overlap) is the opposite of the default: deactivated pages must be hidden (or at least non-interactive and non-overlapping) unless a layer is declared a modal overlay.
- Lyra settings: a `UGameSettingRegistry` of settings, each with a unique `DevName`, `DisplayName` and edit conditions (enabled / disabled / hidden); a `UGameSettingPanel` renders a registry or filtered subset. One panel, categories as tabs, not nested windows. Source: [Lyra Game Settings](https://dev.epicgames.com/documentation/unreal-engine/lyra-sample-game-settings-in-unreal-engine). Tab structure itself is not confirmed on that page.
- Modals (confirm, keep-or-revert) are a separate layer above the page stack with a barrier behind them; Bevy ships exactly this (section 4).
- Focus and gamepad: Xbox guideline 113 requires a highly visible focus indicator that never moves offscreen; 112 says linear menus wrap, 2D grids do not, with an option to disable looping. Sources: [XAG 113](https://learn.microsoft.com/en-us/gaming/accessibility/xbox-accessibility-guidelines/113), [XAG 112](https://devdocs.xbox.com/gaming/accessibility/xbox-accessibility-guidelines/112). Focus must be distinct from hover.
- No-layout-shift rule: no authoritative game source found. It is our own rule (derived from the focus-indicator guidance): hover and focus styles draw inside the existing box (outline, background, inset line) and never change size, padding or border width.
- Main menu to options to sub-page to confirm at Nixxes, CDPR and Larian: not verified (not covered).

## Recommendations for our spec

1. One registry, two views: a feature switch is a typed variable in the existing console/tunables registry with fields name, group, `apply` (live/next load/restart), `audience` (player / dev / cheat), `persist`, and optional `cost` label. Console, F3 panel and options page are views over it. Follows UE `ECVF_SetBy*` and Source `FCVAR_*` flags.
2. Keep the existing layer order (default < preset < user < console < command line). Dev toggles write the console layer and never persist, as Unity's debugger overrides never touch camera data ([Frame Settings](https://docs.unity3d.com/Packages/com.unity.render-pipelines.high-definition@17.0/manual/Frame-Settings.html)); player options write the user layer.
3. A dev toggle may only turn off what the active tier built (Unity rule); expose "unavailable: not built at this tier" as a disabled reason.
4. Declare each costly feature as a named unit (godrays, groundcover, GI, SSAO, clouds, water reflections, shadows) with one GPU pass or CPU system label so the F3/dev panel can show its ms next to the switch. UE keeps these in separate tools (`stat gpu`); putting them in one row is our improvement; measure with the wait-for-driver caveat ([UE GPU docs](https://docs.unrealengine.com/4.27/TestingAndOptimization/PerformanceAndProfiling/GPU)).
5. Dev toggle panel: one list in the F3 overlay, built from the registry, with per-row on/off and `ms`; build it with `bevy_ui_widgets` (checkbox, slider) styled by our flair skin. Feathers (toggle switch, slider, select) is acceptable for the dev surface only. No egui for the player or dev UI by default; `bevy-inspector-egui` stays an optional dev feature.
6. Console parity: `toggle <name>`, `show`-style listing with current layer owner, `sf.reset <name>`, modelled on UE `show` and `ShowFlag.*`.
7. Menu flow: one screen stack where only the top page is active and visible; pages below are deactivated and hidden; the only things allowed to overlay are declared modal layers (confirm, keep/revert) with a barrier. Follows CommonUI stack semantics ([API](https://dev.epicgames.com/documentation/unreal-engine/API/Plugins/CommonUI/UCommonActivatableWidgetStack)) and Bevy `ModalDialog` + `ModalDialogBarrier` (`bevy_ui_widgets-0.20.0/src/modal.rs`). Add a test: pushing a page leaves exactly one non-modal page visible.
8. Options is one panel with tabs (Lyra), not nested windows; a sub-page replaces the panel content, back pops. Settings carry edit conditions with a disabled-reason ([Lyra](https://dev.epicgames.com/documentation/unreal-engine/lyra-sample-game-settings-in-unreal-engine)).
9. Hover and focus never change layout (our rule, from Xbox focus guidance): style via background or inset outline; focus indicator distinct from hover, always on screen; linear menus wrap, grids do not, wrap is optional ([XAG 112/113](https://learn.microsoft.com/en-us/gaming/accessibility/xbox-accessibility-guidelines/113)).
10. Player Graphics page: presets plus computed Custom, per-feature rows grouped by system, each with a short cost class (low/medium/high) taken from the same cost labels once measured; pause screen shows the live world behind the panel for preview (Nixxes applies live per [Laptop Mag](https://laptopmag.com/features/spider-man-remastered-this-is-how-it-runs-on-pc)). Challenge to the 2026-11-11 note: it deferred perf hints; with cost labels already needed for the dev panel, the player hint is nearly free, so do it in the same slice.
