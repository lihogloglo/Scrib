# Doc audit (2026-10-25, docaudit)

Research/plan only. Nothing was moved or edited except this file. Sizes in bytes (tokens ~ bytes/4).
Section sizes were measured with an awk script over `^## ` headings (line numbers are today's).

## 0. Main finding

Almost all the bulk is **as-built logs and dated measurements inside "current truth" files**, in a very regular
shape: `### X as built (<slice>, <date>)` / `## As built (...)` / `**Name (slice, date; target/perf/..)**`. They
move mechanically (heading-bounded blocks), so no judgment is needed to split, and a line-multiset check can prove
nothing was lost. Current-design text is usually the minority. The agent start cost is not the CLAUDE.md files
(fine); it is (a) agents opening a 60-170 KB spec to find one section, and (b) shared docs that the old rule told
everyone to read (ROADMAP 29 KB). The new "read only what the brief names" rule fixes (b); fix (a) needs an index
plus smaller files.

## 4. Discoverability

Today: the specs README is a flat index of 40 rows with long free-text descriptions, status and milestone (8.7 KB),
duplicated per repo; no link from system to crates to adapter to roadmap item to visual-check IDs. Proposal:
- Replace the index with `docs/SYSTEMS.md` (workspace-level, ~8 KB): one row per system: `system | main spec (+section
  anchors) | adapter spec | crates | ROADMAP IDs | visual-check IDs (prefix: SH-, FF-, PH-, GF-, DR-...) | decisions
  tags | research`. Rows generated or checked by script (every spec file listed, every ID prefix mapped), so it
  cannot rot silently. Agents get "the thing they work on" from one grep of one row.
- Each spec starts with a **<= 1 KB "Agent summary"** block: status (one line), what is built vs designed, the crates
  and key types, the 5 decisions that matter, and "read next: section X". Yes, worth it: on a 168 KB spec it is the
  difference between 40 k and 1 k tokens for 80 % of tasks. The summary goes after the title and is exempt from the
  no-loss check (new text only).
- Orchestrator briefs name `SYSTEMS.md` row + section headings; sub-agents read those lines only.
- Keep `bevyrrowind/CLAUDE.md` start-of-session: replace the doc list with "open SYSTEMS.md, grep your row".

## 5. No-loss guarantee

`tools/doc-move-check.py` (or a 40-line Rust xtask; Python is fine, it is not shipped), arguments: original file
(from a copy taken before the move: `cp` to the scratchpad, or `git show HEAD:path` once the repo is merged), then
the list of new files. It does:
1. Read lines, `strip()`, drop blank lines, keep them as a **multiset** (Counter) per side.
2. Allowed additions on the new side only: heading lines (`^#+ `) that are new, lines matching a configurable
   pointer pattern (`^See |^Moved to |^> Moved`, `^\[.*history.*\]`), and the Agent-summary block between
   `<!-- agent-summary -->` markers.
3. `missing = orig - new`: **must be empty** (exit 1 with the lines listed, with their line numbers in the original).
   `extra = new - orig`: printed; every line must match rule 2 or the script fails.
4. Also checks byte total: `sum(new bytes) >= orig bytes - blank lines` and prints before/after sizes, plus a
   dangling-reference check: every `file.md` / `file.md#anchor` / `file.md, "Heading"` reference found anywhere in
   `docs/**` and `CLAUDE.md` still resolves to a file and heading that exists (the script prints unresolved ones;
   fixing them is part of the slice).
5. Output: one summary line pasted into the slice's session file and the commit message ("moved N lines, 0 missing,
   M new heading/pointer lines").
For splits that reorder or rewrite wording (shadows truth pass), the slice instead keeps the superseded text verbatim
in a history file and the check runs against (main + history). The check should be a CI-style gate for the
`docs/` folder: new files over 25 KB (specs) or lines over 400 bytes in ROADMAP warn (separate small lint).
