NPC animation variety

Research, 2026-11-25, from the owner's "old people don't walk like young girls". Full note with sources: docs/research/gameplay-2026-11-25/anim-style.md. Only GTA's clipset mechanism is sourced; RDR2 and TLOU2 internals are inference.

Verdict. No shipped game stores a full clip set for every kind of person in every state. They stack three things: a few authored gait classes (old, heavy, drunk, wounded…), cheap modifiers driven by continuous values (limp, hunch, fatigue, load), and speed and stride warping. The gait classes cost content; the rest is nearly free at runtime. Style is mostly a locomotion problem: sitting, drinking and doors share clips and get their style from the modifiers.
Corrected against owner decisions (the md note carries the same box): 100STYLE is rejected, so no class uses it; Kimodo walk and run are fixed, not replaced; Delirium is adopted and on by default; the clip budget below is a first batch, not a ceiling, because the owner wants a lot of variation.

How to run it: one MotionProfile per NPC

  • style_id: the NPC's gait class, chosen at spawn from race, sex, age and build; stable and saved.
  • Smoothed values that gameplay updates: injury (with a side), fatigue, load, intoxication, mood, age.
  • Selection is a data table, extensible by mods: (class, state) → clip set + modifier values (like UE Chooser tables or GTA clipsets).

Generating the classes

  • Kimodo has no style, age or injury control. Its model card names age bias as a risk and recommends physical wording ("walks slowly with shuffled steps").
  • Consistency within a family (one person's walk, idle and sit-down): a fixed style recipe string in every prompt, the same posture pose as a constraint at the start and end, the same speed envelope, a seed sweep, then an automatic style-score filter on top of the existing foot-slide gates: mean speed, stride, spine pitch and step asymmetry must fall in the family's band.
  • MotionBricks v0.2.0 (NVlabs, late October 2026): adds the SOMA human model (the skeleton we already use), SafeTensors weights, ONNX and an in-betweener demo. Style presets: Zombie, Injured-Leg, Injured-Torso, Skipping, Strafing, Crouch Strafing; no old or drunk. Style is set from a reference pose or clip. Code Apache 2.0; weights under the NVIDIA Open Model Agreement (commercial use allowed); the bundled sample motions are evaluation-only. Needs an NVIDIA GPU, so offline only. Verdict: worth a one-session spike for a consistent limp family; read the paper and the licence on outputs first.

Copying every interaction clip per style would mean 350+ clips for the same look. Modifiers multiply the look (age × fatigue × injury) without adding clips. More classes are data plus one overnight batch; the real limit is filtering and review.

Owner questions

  1. Which gait classes at launch? Recommended: at least neutral, old, heavy, drunk and wounded/limp, plus fatigue and load modifiers; add female and child variants where the neutral set looks wrong. Since you want a lot of variety, more classes can follow as batches.
  2. Do wounded NPCs visibly limp from combat damage, and walk normally again once healed? Recommended: yes for NPCs and companions, by health band; the player's character stays as is until you try it.
  3. How is age assigned? Morrowind records have no age. Recommended: derived from the NPC's id (stable), with overrides in data; class from race, sex and build.
