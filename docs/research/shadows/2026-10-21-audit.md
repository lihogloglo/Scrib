# Rendering + shadows audit (2026-10-21, render-audit session)

Owner ask: "modern rendering, shadows in raster and RT, moving characters and carried torches cast shadows; refactor
everything or not?" Three research agents (code audit, Bevy ecosystem, industry). [F] = sourced, [I] = inference.

## Our stack (code audit)
- ~17.7k LOC Bevy-side render crates, ~11k Bevy-free cores, ~5k shader lines. Only vendored crate: big_space.
- Weather/clouds/froxels, water, terrain, far field: own code with documented reasons; **none is the bottleneck**.
- Shadows: ~14 agent sessions in 9 days, ~3.8k LOC (live ~3.3k, dormant ~0.5k). Live pieces inject into Bevy's
  private render-world state from outside: `sun_view.rs` (extra sun views; source of the interior panic, and its
  `PreprocessingOnly` views are why `NoCpuCulling` regressed to 81 ms), stale-view despawn (#26059), and
  `sf_shadow_cache_bevy` rebuilding Bevy's shadow schedule from `bevy_pbr` internals (8 bugs found in V1 alone,
  uncommitted, gate not met).
- Distance is layered: CSM 250 m -> terrain horizon march 700 m -> CPU SHM 9.2 km -> far static map (off);
  NIF statics have no far hook. Lamps: budget + fade twins + cache + mobility heuristics.
- Frame (s2final, 0 lamps): walk 960p 11.36 ms render-thread bound; walk 1440p TAA 11.08; Balmora standing 12.28
  GPU bound. Sun ~1.2 ms, one uncached lamp ~1.5-1.9 ms (6 root views x ~0.35 ms). Census 8 cached lamps +6.5 ms
  **GPU** (main-pass lamp sampling, ~0.8 ms/lamp: not diagnosed; caching can't fix it). Draw calls per view
  never recorded.
- RT (Solari) not wired to the streamed world; skinned meshes not traced (no character RT shadows); point lights
  via proxy spheres; duplicate RT meshes lose vertex colour; terrain invisible to RT.

## Bevy (0.20, 2026-10-08; 0.21 ~Feb-Mar 2027 [I])
- No upstream shadow caching, atlas or virtual shadow maps; not on JMS55's stated plans. [F]
- #25576 (each point/spot face a root view running Core3d), #26149 (`Core3dShadows` slim schedule, open),
  #26161 (skip unchanged point/spot maps: 16 static point lights 11.5 -> 2.5 ms, open, blocked on #26149),
  #26059 (leaked views), #26257 (preprocess bind groups rebuilt per frame), #26182 (StandardMaterial never
  bindless on DX12). All open/untriaged. [F]
- Solari 0.20: rewrite, unified ReSTIR DI/GI path tracer, DLSS-RR denoise (NVIDIA only in practice). Main (0.21):
  point/spot/rect lights (#25913), alpha mask (#25996). **Skinned meshes skipped, no date**; JMS55 suggests forking.
  0.18 numbers: 7.3-14.1 ms on a 3080 at 900p, DLSS-RR ~6.1 ms of it. [F]
- wgpu 30: ray query still experimental (Vulkan dependable), MDI-count stable, MULTIVIEW native (one pass for 6
  cube faces possible, Bevy doesn't use it), no sparse resources (VSM would be software page tables). [F]
- No public Bevy/wgpu project with cached/virtual shadow maps or RT shadows found. Tiny Glade: Bevy ECS + own
  Vulkan renderer (not a model for us). [F]

## Industry (2022-2026)
- Every well-regarded open world uses **raster shadow maps for the sun by default**; RT budget goes to **GI**
  first (Crimson Desert per-pixel RTGI; AC Shadows RTGI; idTech RTGI with raster shadows, RT shadows only in PT
  mode; KCD2 SVOGI, no HW RT). RT shadows come as a top PC tier: sun first, all lights later (Indiana Jones,
  Cyberpunk RT -> Overdrive ReSTIR DI). [F]
- Crimson Desert's shadows were criticised (near pop-in, grainy indoor noise even with RT off). [F]
- Sun standard: CSM with per-cascade update scheduling + static/dynamic cache, interval-based cascade selection,
  distant cached map or heightfield shadows (Cyberpunk SIGGRAPH 2021: 4 cascades + 4 distant levels refreshed
  every few seconds, spread over frames; CryEngine cached cascades). [F]
- Local lights standard: one **cached atlas**, fixed per-frame update budget, static/dynamic slices, per-face
  dirty (Doom 2016 8k atlas, Cyberpunk, HDRP cached/mixed modes). Shipped counts ~4-16 shadowed local lights;
  candles mostly unshadowed. Player torches: Skyrim/Elden Ring vanilla cast none; when shipped, one dedicated
  low-res every-frame cube, short radius, self-mesh excluded. [F]/[I]
- Grounding: contact shadows (Bend/Days Gone, Bevy 0.19), GTAO, **capsule shadows** for characters (UE, TLOU
  ellipsoids), per-object hero shadow (CryEngine 0.25 ms on XB1). [F]
- RT shadows on mid HW: hybrid (AMD FidelityFX Hybrid Shadows: rays only in penumbra tiles) + SIGMA (0.40 ms at
  1440p on a 4080 -> ~0.5-0.7 ms on a 4060 laptop at DLSS-Q [I]); skinned BLAS refit per frame within ~40 m. [F]/[I]

## Conclusion (render-audit)
No renderer rewrite: the non-shadow systems aren't the problem and the 0-lamp walk is ~at target. Reset the
shadow lane: stop injecting from outside; own Bevy's shadow path through a vendored `bevy_pbr` patch (like
big_space) carrying #26149/#26161, then a cached local-light atlas with a per-frame budget, cascade update
scheduling, world-size PCSS, GTAO + capsule shadows, a dedicated torch cube. Delete the layers it replaces.
RT stays on the Solari track (0.21 lights); character RT shadows need a compute skin cache + BLAS refit
(upstreamable) and wait for Phase 4.
