Context handoff size

Meta-2, 2026-11-26. Owner question: is 200k the right point for a session to hand off? Model: Claude Opus 5.5 in Claude Code on a subscription.

Recommendation: keep ~200k for lane orchestrators. That is close to the cost optimum, and the optimum is flat: from 150k to 250k, the cost per unit of work changes by under ~10%. Keep the hard ceiling of 250k (+11% at 300k, +30% at 400k). For the meta-coordinator, use ~150k: it adds little per turn and sits idle between messages, so it loses the cache more often.

Facts from sources

  • Opus 5.5 prices per MTok: input $4, 5-min cache write $5, 1-h cache write $8, cache read $0.20 (0.05x input, half the usual 0.1x), output $20.
  • No long-context price tier for Opus 5.5. "Claude 4.6 and later models (except Claude Haiku 5.5) … include the full 1M token context window at standard pricing. (A 900k-token request is billed at the same per-token rate as a 9k-token request.)" Only Haiku 5.5 charges more above 100k. Price alone sets no cliff at 200k.
  • Cost per turn grows with context. Claude Code docs: "Claude Code sends your full conversation with every request, and each time Claude uses tools it sends another request … Claude Code re-reads that history at the cached token rate." Every tool call reads the whole context again, so a session's total cost grows with the square of its length.
  • Subscription usage: the docs say long sessions "use far more of your plan limits" for this reason, and name the same causes. Claude.ai, Claude Code and Desktop share one 5-hour window and one weekly window. Anthropic does not publish how cached tokens are weighted against plan limits. This report assumes they count in proportion to their API price.
  • Cache misses: the first request after an idle gap longer than the cache lifetime "reprocesses your full context". A message from another session to an idle session also "sends your full context each time". On the meta's long idle waits, a miss at 200k means rewriting the whole context: about $1.60 at the 1-hour write rate, against $0.04 for a cache read.

Model

Say a session starts at C0 (prompt, CLAUDE.md, CONTRIBUTING and the handoff it reads: ~40k). Context grows by g tokens per request (tool results plus output), and the session hands off at H. Reads cost r = $0.20/MTok per token of context per request. A handoff has a fixed cost F: the successor writes its starting context again, the old session writes the handoff, and the new one re-reads files to re-orient. That comes to about $0.5-1.5 in token terms.

Cost per token of progress = r·(H+C0)/(2g) + F/(H−C0). It is lowest at H − C0 = √(2·g·F / r).

How flat the curve is, for a typical lane (cost relative to the optimum): 120k +18%, 195k 0%, 250k ~+4%, 300k +11%, 400k +30%.

What the model leaves out

  • Cache misses push the point down. Each miss costs about 40x a cache read, multiplied by the context size. Sessions that wait idle for a long time (meta, lanes waiting on CI or the owner) should sit at the low end.
  • Lost understanding pushes it up. If a successor re-derives work or repeats mistakes, F grows. A good handoff file (CONTRIBUTING's ~2 KB) keeps F small.
  • Answer quality is not priced here. Very long contexts can make attention to early instructions worse. This analysis has no measurement of it, and it would also argue for not going far above 200k.
  • Sub-agents end naturally at the end of their slice (one deliverable per brief), so this mainly applies to orchestrators.
