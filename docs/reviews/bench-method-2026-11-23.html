2. Are repeats needed? Measured

Script over every summary.md in bevyrrowind/target/perf/* and bevyrrowind/benchmarks/runs/* ("Runs" table; spread = max - min of run medians within one arm and scene; 405 groups of 2-5 runs, all 2026-11-17+):

Runs in an arm do read the same value (gc_b4: 0.06-0.23 ms per arm). Every large spread is a discrete fault, not noise: GC-P0 bistable GPU state (11.5 vs 36.7 ms), lampsel_new 10.3 vs 106.7, contaminated suites. A 3x jump shows in one run: a bug to log, not a reason to average. One paired run in gc_b4 gave +0.08 to +0.53 ms for a true ~+0.27: one launch per arm settles >= 0.5 ms, not a 0.25 ms cost.

Rule: one run per arm. Run a second launch only if the harness flags the run (§4) or the delta is within 0.5 ms of a decision (default on/off, budget). Costs under 0.5 ms are measured in-process (§3) or from GPU pass timers, never with more launches. The dirt the 11-16 audit found (blocked arms, unfocused window ~65 vs ~85 fps, other sessions) is caught by interleaving and hygiene, not repeats.

3. In-process A/B (the default A/B tool)

Shape: one launch, scenario warm-up, then the switch flips every N s (A B A B ... >= 4 phases each, 5 s), first cycle discarded (pipeline compiles on the first flip), per-phase median, p99, hitches, main / render / GPU and GPU passes; Δ = median of paired (B - A) phases. ABAB cancels thermal drift. ~20 s load + 3 s warm-up + 45 s = ~70 s.

What exists: the switch probe (mw_devtools_bevy/src/switch_probe.rs) measures every flip, mean frame / main / render / GPU over 2 s before vs 2 s after a 0.5 s settle (WINDOW_S :39, SETTLE_S :46, NOISE_MS 0.5 :53), flags a camera move (STILL_M :60); quick A/B = 3 off/on rounds, median cost (AB_ROUNDS :74, start_quick_ab :319). Missing: (a) needs the Features panel open and a click (:275), no CLI or scenario entry; (b) feature switches only, not any Lifetime::Live tunable; (c) 2 s means, no p99 / hitches / GPU passes; (d) result only in an info! line, no report file; (e) standing camera only (a walk needs one path lap per phase).

Not live (refused at switch_probe.rs:337: startup_hint, Lifetime::Restart | Bake): Kind::Removed parts (part_switches.rs:41-81: groundcover, underwater, farshadows, shadows, gi) and every part.* startup row. For these: perf suite 1 run per arm, interleaved, same exe; and make the costly ones live (built, systems skipped by a run condition, as froxels or blades already are) one slice each.

4. Hygiene instead of repeats

Already checked per run (perf/cli.rs:558, retry on dirty :371): no build / game process, other CPU <= 25 %, GPU idle before, window focused, power plan and mode recorded (perf/power.rs). Add, each refuse (R) or flag (F):

  • R: on battery or power mode not best performance.
  • F -> one rerun: GPU clock or W drops > 10 % from the run's first 2 s; pipeline compiles in the measure window (a warm-up gate, so one warm-up launch per new exe, not per arm); frame > 1.5x the scene's stored baseline (catches the bistable fault without peers; today's outlier check needs repeats, cli.rs:599,669).
