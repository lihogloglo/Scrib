# Worldgen: what was done on 2026-11-18/19

The world generation lane in one page: what exists, what the owner decided, what is next. Details live in the spec
(`superfargoth/docs/specs/worldgen.md`, "Handoff"), the ledger (`docs/ledger/worldgen.md`) and the visual checks
(`bevyrrowind/docs/visual-checks/worldgen.md`).

## Goal (owner)

Vvardenfell at 10x (~50 x 50 km) through a generic, deterministic generator (`sf_worldgen`): nature is regenerated
between kept human-made places (towns, tombs, wrecks) at 1:1. Constraints: fast, easy to iterate, geologically logical
and detailed land, important natural features kept (Red Mountain and its crater, the Caldera crater, foyadas, the
Odai, lakes, bays).

**Owner direction (2026-11-19):** don't nail the terrain now. Every later step (settlements, forests, textures) is
procedural and regenerates from whatever terrain we pick, so any terrain works as long as that chain is deterministic
and regenerates without bugs. Working island: `target/worldgen/vo/V3` (WG-VO stratovolcano, owner "very promising").
Live reload loop and hand edits: later.

## Built (first session, commits 4fc64dec, 0fdbcf23)

- `mw_worldgen` + `bevyrrowind worldgen-dump`: Morrowind LAND mosaic at 1.83 m, regions, markers.
- `sf_worldgen` + bin `scrib-worldgen`: stream power erosion, Veloren LEM port, layout/uplift landscape, parametric
  stratovolcano (caldera, sub-peaks, collapse scar, rifts, ravines), WG-F analytic erosion filter, DEM import (real
  Etna/Teide/Iceland, local only), `measure` (real vs generated statistics).
- 3D viewer `bevyrrowind worldgen-view` (arms on keys 1-9, markers, figures, cone trees, haze).

## Done this session (uncommitted until this commit)

- **Landmarks:** gazetteer of Vvardenfell's natural features (`docs/research/vvardenfell-landmarks-2026-11-18.md`) and
  a landform census `scrib-worldgen landforms` that detects craters, trenches, lakes, peaks and bays (553 features on
  the source in 1.1 s). Finding: erosion on V3 erases the craters and trenches, so landmarks must become generator
  constraints (WG-L2c, later); the detectors double as survival checks.
- **Terrain-diffusion (ML, MIT, SIGGRAPH 2026):** TD-1 (stock/injection on our guides, 23 s per island on the 4060),
  TD-2 (decoder inversion + masked RePaint keeps landmarks; 15 min per crop), **TD-3: the published encoder
  (`xandergos/terrain-diffusion-autoencoder`, 2026-08-21) works with the 30 m decoder (corr 0.99 on Teide/Etna, < 1 s)**,
  which replaces the slow inversion. The first TD-2 write-up wrongly said no encoder existed (corrected). Other
  published models: 90m and 90m-pool2 (coarser), an ONNX export. Not pursued further today; owner look pending.
- **G1: the generated island in the game renderer.** `bevyrrowind view "world:<guide dir>"` streams a guide as game
  terrain through a new `sf_terrain::TerrainTiles` provider (the bake store is one implementation, the generated
  `sf_worldgen::tiles::GuideTiles` another), with the game's sky, atmosphere, clouds (base raised 2.5 km for the 5.5 km
  summit), sea and weather. No Morrowind content in that world. Owner look: runs, fps good, many hitches, erosion
  detail not visible (finest octave was 20 m; CPU tiles ~84 ms each in game).
- **G2: GPU fill.** For generated worlds the clipmaps fill on the GPU (`tiles.wgsl`, a mirror of `filter.rs`; GPU vs
  CPU max 3.7e-4 m), CDLOD bounds are analytic, and a CPU twin on 2 threads gives heights for queries and physics
  near the player. Runtime filter 8 octaves, 160 m down to 1.25 m (final resolution, 0.5 m vertices). Old CPU path:
  `--off gputerrain`. Live console toggles `worldgen.filter`, `worldgen.octaves`. **Built, not yet looked at.**
- **The Morrowind path is unchanged:** baked tiles, CPU fill (`BakedTerrain::gpu_field` is `None`); the changes it
  passes through are a provider indirection and a fallback layer used only without BC compression.

## Owner decisions today

- A generated 10x world may ship baked (transformative, like a mod); raw source data never ships.
- Etna/Teide as references, Iceland rejected; summit ~5.5 km; WG-F filter kept.
- Work in the game renderer, not the viewer; determinism is essential (gameplay heights from the CPU, the GPU is look
  only); trees: several species, many of them (against the "it's empty" effect), raise the count gradually.
- Quick reviews only, no fleets of audit agents.

## Known issues found along the way

- `sf_terrain_bevy tests::terrain_gate_keys_on_camera_tiles_and_origin` fails ("off by default until the owner's A/B"):
  pre-existing, not from this work.
- G2 limits: height edits ignored on the GPU path; mid-range CPU queries (~0.8-1.5 km) read a coarse level and can be
  a few metres off the rendered surface; a physics chunk built before its level-0 twin tile arrives keeps coarse
  heights; `worldgen.*` tunables not in the devtools CATALOG (startup warning); guide size limited by one 128 MiB
  storage binding. Water in generated worlds has no shore bake (open-water optics only); weather regions are still
  Morrowind's raster.
