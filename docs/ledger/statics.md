## Standing facts

- Statics are the single biggest lever: `--off statics` walk 7.21 ms vs 10.95 (3.7 ms, mostly CPU: PostUpdate visibility scans +2.9 ms, render +3.8 ms traced).
- Mesh count is not the cost: precombine halved entities (46 k -> 25 k) and the frame did not move; `--scene` cut meshes 24.6 k -> 15.0 k and reached only parity (walk 11.07 vs 10.71).
- `--scene` is opt-in and at parity; its measured win is pacing (stutters 28/min -> 0-8), not ms. Remaining gap work: range count per batch, dispatch width = capacity x views (S3a3 compaction parked).
- `NoCpuCulling` on statics failed twice (81 ms in 2026-10; 113 stutters/min in 2026-11): every view must GPU-cull, and `NoIndirectDrawing` views never do.
- Bins are ~1/3 of items (2.2-2.9 items per bin), so "one batch per model" is precombine again; batch granularity decides the scene's win.
- `--scene` holds STAT statics only; doors, containers, lights, items and actors stay entities. It has no LOD, size cull or handoff end yet (every batched static draws LOD 0 to its cell's edge).
- Far field is not optional: without it Balmora costs 20-22 ms and 353 k entities; it is a fixed ~1.2 ms GPU at 400 m `d1`.
- The 2026-11-09 "~41 % fps from horizon culling" figure from the Greatness7/MGE fork is bundled with LOD, atlasing and merging; do not quote it in a budget.
